# Deep Reader｜英文閱讀夥伴

使用者常丟來英文論文、文章或小說（PDF、網址或直接貼上的文字），需要真正讀懂它。這個 skill 把原文轉成**一個可以直接在瀏覽器打開的 HTML 檔**，使用者要的每個模式都是檔案裡的一個**頁籤**，不會產出多個檔案。

| 頁籤 | 觸發說法（範例） | 內容 | 細節規格 |
|---|---|---|---|
| **Key Points**（重點整理） | 重點整理、重點、摘要、這篇在講什麼、讀書筆記 | 五個區塊，每塊一小段或簡短條列：Argument、Argumentation、Evidence、Structure、Key Insights | `references/mode-summary.md` |
| **Translation**（中英對照） | 翻譯、中英對照、雙語、全文翻成中文 | 左英文原文／右中文譯文，逐段對齊 | `references/mode-translate.md` |
| **Annotated**（重點批註） | 批註、導讀、worksheet、作業題目、讀書報告 | 左原文（依題號彩色高亮）／右逐段英文批註＋底部答題索引 | `references/mode-annotate.md` |
| **Logic Map**（邏輯梳理） | 邏輯、論證、結構、脈絡、看不懂作者在說什麼 | 核心主張、論證地圖、推進脈絡、Toulmin 拆解、論證檢驗 | `references/mode-logic.md` |

使用者可以一次要多個模式（例如「翻譯＋邏輯梳理」），全部放進同一個檔案的不同頁籤。

## 工作流程

### 1. 判斷要哪些頁籤
從使用者的話判斷要哪些模式。如果只丟了檔案或連結、沒說要做什麼，用一句話問：「要做哪些：① 重點整理、② 中英對照翻譯、③ 重點批註、④ 邏輯梳理，還是全部？」——這比猜錯後產出一份長篇錯誤結果更省使用者的時間。

### 2. 取得完整原文
讀 `references/input.md`，照其中的方法取得並清理原文（PDF 抽字、網頁正文擷取、去除頁首頁尾與斷字）。重點是**拿到完整、分段正確的原文**：每個頁籤的品質都建立在段落切分上。若 PDF 是掃描圖檔、網頁需要登入或被擋，直接告訴使用者並請他改貼文字，不要憑印象補寫原文。

### 3. 補齊模式需要的資訊
- **重點批註**需要「題目」和「課程資訊」。使用者若有提供 worksheet／作業題目，照原題使用；若沒有，自行擬 4–6 題能抓住全文骨幹的英文導讀題，並在頁面上標註 `AI-drafted guiding questions`。不要因為缺題目就停下來等。
- 其他模式不需要額外資訊。

### 4. 讀取規格，寫出每個頁籤的內容
1. 讀每個要做的模式的 `references/mode-*.md`（內容規格、品質標準、該頁籤的 HTML 結構範例）。
2. 每個頁籤各寫一份 HTML 片段，只包含該頁籤的內容（規格中「這個頁籤的 HTML」那一段）。**只用規格裡定義的 class 名稱**，模板的樣式與互動才會生效。
3. 段落錨點加頁籤前綴：翻譯用 `tr-pN`、批註用 `an-pN`，避免同一個檔案裡 id 重複。

### 5. 組裝成一個檔案並交付
模板是 `assets/reader.html`：已含所有頁籤的 CSS 與互動 JS（頁籤切換、記住上次的頁籤、跨頁籤的 `#` 連結），只留兩個佔位符 `{{TITLE}}` 與 `{{BODY}}`。依你所在環境選一種方式（能寫檔就寫檔）：

- **可執行程式碼**（Claude Code、Codex、Claude.ai / ChatGPT 的程式執行環境）：用腳本組裝，它會產生標題列與頁籤列、包好每個頁籤、補上錨點前綴，並檢查標籤是否成對：
  ```bash
  python scripts/build_page.py --title "論文標題" --subtitle "Author · Year · Course" \
    --summary summary.html --translate tr-01.html tr-02.html \
    --annotate annotate.html --logic logic.html --out paper-reader.html
  ```
  只給有產出的模式；頁籤順序固定為 Key Points → Translation → Annotated → Logic Map。
- **可寫檔但不能執行程式**／**純聊天介面**：自行組裝。把模板的 `{{TITLE}}` 換成標題，`{{BODY}}` 換成下面的骨架（沒做的模式，就把它的按鈕和 section 一起拿掉）：
  ```html
  <header class="appbar">
    <div class="appbar-inner">
      <div class="app-title">Paper Title<small>Author · Year · Course</small></div>
      <nav class="tabs" role="tablist" aria-label="Views">
        <button type="button" role="tab" data-tab="tab-summary" aria-controls="tab-summary">Key Points</button>
        <button type="button" role="tab" data-tab="tab-translate" aria-controls="tab-translate">Translation</button>
        <button type="button" role="tab" data-tab="tab-annotate" aria-controls="tab-annotate">Annotated</button>
        <button type="button" role="tab" data-tab="tab-logic" aria-controls="tab-logic">Logic Map</button>
      </nav>
    </div>
  </header>
  <section class="panel" id="tab-summary" role="tabpanel" aria-label="Key Points">…重點整理片段…</section>
  <section class="panel" id="tab-translate" role="tabpanel" aria-label="Translation">…翻譯片段…</section>
  <section class="panel" id="tab-annotate" role="tabpanel" aria-label="Annotated">…批註片段…</section>
  <section class="panel" id="tab-logic" role="tabpanel" aria-label="Logic Map">…邏輯片段…</section>
  <footer class="app-foot">Generated by deep-reader · A study aid — check it against the original text</footer>
  ```
  純聊天介面：若平台支援 Artifact／Canvas，放進去；否則輸出一個完整的 ```html 程式碼區塊，請使用者存成 `.html` 後用瀏覽器開啟。

檔名建議：`<短標題>-reader.html`（短標題用英文小寫加連字號）。之後使用者要追加其他模式時，重新組裝同一個檔案、多一個頁籤，不要另開新檔。

交付後在對話中用 3–5 行說明（用使用者對話的語言）：檔案裡有哪些頁籤、全文的一句話主旨、以及任何需要使用者注意的事（例如 PDF 某頁抽不到字、題目是 AI 擬定的）。不要在對話裡重貼整份內容。

## 長文處理

一篇 20 頁的論文翻譯後可能超過單次輸出上限。處理原則：

- **翻譯模式必須完整**：不可省略、摘要化或寫「（以下略）」。這是使用者最在意的一點——他們要逐段對照原文，缺段就失去意義。
- 以章節為單位分批產出：翻譯頁籤可以寫成多個片段檔（`tr-01.html`、`tr-02.html`…），`build_page.py --translate` 依序串接。這樣即使中途被截斷也能接續。
- 純聊天介面無法寫檔時：先告知共分幾部分，每則回覆輸出一部分，最後一部分附上完整組裝說明（或在最後一則輸出完整檔案）。
- 批註與邏輯頁籤可以對次要段落合併處理（例如「¶12–14 Literature review」一張批註卡），但核心論證段落要逐段處理。
- 參考文獻（References / Bibliography）保留英文原樣、不翻譯，放在可摺疊區塊中。

## 輸出語言

- **只有譯文是中文，其他一律英文。** 翻譯頁籤的右欄譯文、中文標題、術語表的中文譯名、〔譯注〕用中文；其餘所有產出——標題列與頁籤名稱、各頁籤的介面文字、整份重點整理、批註頁籤的題目／圖例／批註卡／答題卡、整份邏輯梳理——都用英文。即使使用者用中文跟你對話也一樣。
- 英文產出要清楚易讀：使用者的母語不是英文，用短句與常用字，專業術語第一次出現時用一句話解釋。
- 使用者明確要求某部分改用其他語言時，照使用者的要求。

## 翻譯原則（翻譯頁籤）

- 譯文預設**繁體中文（台灣用語）**。使用者以簡體中文提問或明確要求時改用簡體。
- 專有名詞與關鍵術語第一次出現時寫成「中文（English）」，之後用中文；人名第一次出現保留原文。
- 行文引用（Smith, 2020）、數學式、程式碼、變數名稱、書名原文保持不變。
- 小說與文學作品：保留語氣、節奏、對話口吻與修辭，不要為了「好懂」而改寫成說明文。
- 學術文章：精確優先，其次才是流暢；遇到歧義，在譯文後用〔譯注：…〕簡短說明。

## 品質自我檢查（交付前）

- 只產出**一個** HTML 檔，每個模式是一個頁籤；段落 id 沒有重複（`tr-pN`／`an-pN`）。
- 原文段落數與輸出段落數一致（翻譯頁籤逐段對齊，沒有漏段）。
- 每個 PDF 換頁處都檢查過：停在半句的段落已和下一頁的後半句接回成同一段，沒有被拆成兩段或漏翻後半句。
- 除了翻譯頁籤的譯文欄、中文標題與術語表譯名，頁面上沒有中文（介面、重點整理、批註、答案、邏輯梳理都是英文）。
- 所有 `<mark>`、題號標籤、批註卡的顏色 class 與圖例一致（批註頁籤）。
- 重點整理與邏輯梳理的主張與步驟彼此一致。
- 引用的原文句子確實出自原文，段落編號對得上——使用者會拿來寫作業，錯誤引用比沒有引用更糟。
- HTML 用瀏覽器開啟不會跑版：標籤成對、沒有殘留的 `{{…}}` 佔位符。
