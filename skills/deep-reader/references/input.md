# 取得與清理原文

三個模式都以「段落」為基本單位，所以第一步是拿到**完整且分段正確**的原文。

## 來源判斷

| 使用者給的 | 優先做法 | 備援做法 |
|---|---|---|
| PDF 檔 | 平台內建的檔案閱讀（Claude / ChatGPT 上傳檔案都能直接讀） | `python scripts/extract_text.py paper.pdf -o paper.txt` |
| 網址 | 平台內建的網頁擷取／瀏覽工具 | `python scripts/extract_text.py https://... -o article.txt` |
| 直接貼上的文字 | 直接使用 | — |
| 指向 PDF 的網址（如 arxiv.org/pdf/...） | 下載後當 PDF 處理 | `extract_text.py` 會自動判斷 content-type |

`scripts/extract_text.py` 只依賴 Python 標準函式庫；處理 PDF 時會依序嘗試 PyMuPDF (`fitz`)、`pypdf`、`pdfminer.six`，都沒有的話會提示安裝指令（`pip install pymupdf`）。

## 清理規則

PDF 抽出來的文字通常很髒，交給後續模式前先處理：

1. **重建段落**：PDF 每一行都是硬換行。把同一段內的行接起來；空行、縮排、或上一行明顯較短且以句號結尾時才視為新段落。
2. **接回跨頁段落**（最容易出錯，務必逐頁檢查）：頁面最後一段若沒有以句號、問號、驚嘆號結尾（例如停在 `...computed as a weighted sum`），代表這句話延續到下一頁。下一頁開頭常先出現頁首、圖表標籤、圖說、表格或註腳，真正的下半句（例如 `of the values, where...`，通常以小寫開頭）排在它們後面。把下半句接回上一頁那段，合成**一個**段落；夾在中間的圖說、表格放到合併後的段落之後。
   - 不要把下半句當成獨立段落，更不要因為它「看起來不完整」就略過——這正是跨頁段落翻不出來、譯文少半句的原因。
   - 若下一頁開頭是新的章節標題，代表上一段確實在頁尾結束，不要合併。
   - 真的找不到下半句時，照樣翻譯上半句，並在譯文後加〔譯注：原文此處跨頁，下半句未能擷取〕，讓使用者知道要回原文核對。
   - `extract_text.py` 會自動接回大部分跨頁段落，並在 stderr 顯示「re-joined N paragraph(s)」；它在無法確定時寧可不合併，所以仍要檢查 `[[page N]]` 標記前後是否有斷句。
3. **修復斷字**：行尾的 `exam-` + 下一行 `ple` → `example`。但保留真正的連字號複合詞（`well-known`）。
4. **去除雜訊**：頁首頁尾（每頁重複的期刊名、作者名、頁碼）、浮水印、「Downloaded from ...」、行號。
5. **雙欄排版**：學術 PDF 常是雙欄，確認閱讀順序沒有左右欄交錯。若句子明顯接不起來，依語意重排；欄與欄之間的斷句比照第 2 點接回。
6. **標題與結構**：辨識章節標題（1. Introduction、2.1 Method…），它們在輸出中要成為獨立的標題列。
7. **圖表**：保留圖表說明（Figure 1: ...、Table 2: ...）作為獨立段落；表格內容若抽得出來就保留，抽不出來就註明「〔表格內容見原文第 N 頁〕」。
8. **註腳**：移到該段之後或文末，以 `[n]` 標示。
9. **參考文獻**：辨識 References / Bibliography / Works Cited 區塊，保留原樣，不翻譯、不批註。

## 段落編號

清理後替正文段落依序編號 `¶1, ¶2, …`（標題、圖說、參考文獻不佔編號）。這個編號會出現在三種輸出中，讓使用者能交叉對照，也讓模式 2 的證據引用有明確出處。

## 需要停下來告知使用者的情況

- PDF 是掃描圖片、抽不出文字（抽出的字數遠少於頁數 × 200）：告知使用者，建議提供可選取文字的版本或直接貼上文字。若平台能直接看圖（多模態），可以改用看圖辨識，但要說明可能有辨識錯誤。
- 網頁需要登入、付費牆、或被阻擋：請使用者貼上全文。
- 文件非常長（例如整本小說、超過 80 頁的論文）：先確認要處理的範圍（哪幾章、哪幾節）。

在這些情況下不要憑記憶或網路上的摘要補寫原文——使用者要的是對照「這份」文本，杜撰的原文會讓整份產出失去價值。
